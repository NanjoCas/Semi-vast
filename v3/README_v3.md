v3 来自对 v2 训练逻辑的全面审查（`../v2/README_v2.md` 第 9 节）。v2 每跑一轮都会发现新问题：O ≈ A、LogicScore 下标错误、L 组崩溃、训练噪声大于要检验的效果。v3 的做法是：

1. **先修正审查发现的全部问题，再跑实验**；
2. **方案在跑之前定死**：检验什么、用什么判据，都在第 4 节写好，不事后挑选；
3. **每次运行自动检查**（第 6 节），问题在运行结束时直接报出来，不用再人工翻日志；
4. **先试跑、过关再跑主实验**（第 5 节），试跑的通过标准也事先写好。

v3 是独立目录，没有改动 v2 的任何文件。数据构建、SSL 划分、extractor、伪标签生成与 v2 完全相同，所以 v2 在新数据集上已经生成的伪标签池（seed 42–44）可以直接导入复用。

## 3. 相对 v2 的改动

### 3.1 detector 的初始化（M1）

- `training.detector_init_from_nli: true`：detector 的编码器从 `cross-encoder/nli-deberta-v3-large` 加载（与 extractor 相同），加载失败直接报错，不会悄悄退回原始模型。
- `training.detector_freeze_layers: 6`：与 extractor 一样冻结编码器前 6 层（词嵌入不冻结）。
- 结果文件记录 `encoder_source` 和 `frozen_layers`，可以核对。
- 与 extractor 仍有的差别：分类头（detector 为两层 MLP，extractor 为单层线性）、训练预算（detector 按步数）、动态补齐。试跑标准 C3 检查 A 的验证 F1 是否不低于 extractor。

### 3.2 固定训练预算（M2）

- 每个组都训练 `training.detector_total_steps = 640` 次参数更新（v2 中 O 的步数），每 `eval_every = 40` 步在 dev 上评估一次，共 16 次，取验证 macro-F1 最高的一步。
- 每一步 = 1 个有标签 batch（16 对）+ `pseudo_ratio = 3` 个伪标签 batch（48 对）；A 只有有标签 batch。两个 loader 都循环使用。
- warmup（10%）与线性衰减、λ 从 0.3 线性升到 0.7，都按同一个总步数计算，**所有组完全相同**。
- 代价：小集合会被反复使用。640 × 48 = 30,720 次抽样：Q / K 约 650–750 条，平均每条约 40–47 次；B 约 1,157 条，约 27 次；O 3,855 条，约 8 次。Q 与 K 规模相同，所以这一点不影响 H2 的比较；dev 上的模型选择会挑在过拟合之前的那一步。

### 3.3 损失（M3）

- 监督损失：带类别权重的 CE。权重 = `(N / (3·n_c))^1.5` 后归一化到均值 1，与 extractor 完全相同（`common.data_utils.class_weights_from_labels`，已与 extractor 日志中的权重逐位核对）。
- `algorithm.logit_adjust_tau: 0`：关闭 logit adjustment。代码中的符号已改为训练时 `logits + τ·log π`（Menon et al., 2021），以后需要时可以打开。
- 伪标签损失：普通 CE，配合平衡采样器（与 v2 相同）；不再做 logit adjustment。
- `imbalance.pseudolabel_prior_tau`：伪标签生成时的先验校正改用独立的键。v2 中它与 detector 损失共用 `algorithm.logit_adjust_tau`，改损失会悄悄改变伪标签。这个校正默认关闭，所以伪标签与 v2 完全相同。

### 3.4 选样（M4）

| 组 | 定义 |
|---|---|
| B | 池中置信度最高的 `confidence_top_fraction = 30%` |
| Q（L-q） | 在 B 内：SUPPORTS、REFUTES 各自按方向一致性 c 降序保留前 `consistency_quantile = 50%`；NEI 全部保留（c 对 NEI 没有区分能力，v2 README 8.6） |
| K | 按置信度取前 \|Q\| 条（因此 K ⊂ B，且 \|K\| = \|Q\|） |

- c 的定义不变：伪标签为 SUPPORTS 时 c = LS，REFUTES 时 c = −LS，NEI 时 c = 1 − \|LS\|，LS = P(蕴含) − P(矛盾)。
- 排序在置信度或 c 相同时按 id 打破平局，结果与文件中的顺序无关（已验证）。
- 在 v2 的伪标签池上离线计算（条数 / 准确率 / 平衡后准确率）：

  | seed | B | Q | K | Q − K（平衡后） |
  |---|---|---|---|---|
  | 42 | 1156 / 0.535 / 0.519 | 712 / 0.622 / 0.619 | 712 / 0.522 / 0.557 | +0.062 |
  | 43 | 1157 / 0.659 / 0.667 | 743 / 0.724 / 0.746 | 743 / 0.664 / 0.682 | +0.064 |
  | 44 | 1157 / 0.644 / 0.637 | 642 / 0.726 / 0.707 | 642 / 0.620 / 0.626 | +0.081 |

  B 的规模在各 seed 间一致（v2 为 712 / 2650 / 1212）；B 中最低的置信度为 0.654 / 0.897 / 0.704。

### 3.5 工程（M5、M6）

- 最佳权重复制到 CPU 内存，训练结束后直接评估测试集，不再反复写 1.7GB 的 checkpoint；需要保留时加 `--keep_checkpoints`。
- 有标签 loader `drop_last=True`。
- `--train_seed`（`run_all.py` 中为 `--extra_train_seeds`）：同一划分换训练 seed 重复训练，结果写到 `<组>_t<seed>`，只用于估计训练噪声，不进入组间比较。

### 3.6 没有改动的部分

数据构建（`data_prep/`）、SSL 划分、extractor 的训练、伪标签生成、LogicScore、Discourse 与 v2 完全相同。W / R / C（复合权重与 RL）的代码也保留原样，但它们仍是 v2 的设计（复合权重用不带方向的 \|LogicScore\|、RL 奖励近似常数），不在默认方法列表中，结果不能用于结论（第 8 节）。

## 4. 消融组与事先确定的检验

| 组 | 含义 |
|---|---|
| A | 纯监督（与 extractor 同样的初始化和损失）——最强的纯监督基线 |
| B | 置信度前 30% 的伪标签 |
| Q | B 内按 c 选：SUPPORTS / REFUTES 各留一半，NEI 全留 |
| K | 与 Q 同规模，按置信度选 |
| O | 整个无标签池用金标签——上界 |

| 编号 | 比较 | 回答的问题 |
|---|---|---|
| H1 | B − A | 伪标签在最强的纯监督基线之上是否有效 |
| **H2** | **Q − K** | **同样规模下，LogicScore（c）能否选出更有用的伪标签（主要检验）** |
| H3 | Q − B | 用 c 过滤（更小但更准）是否优于不过滤（次要，混有规模差异） |
| — | O − A | 提升空间 |

- **主指标**：测试集整体 macro-F1。**次要指标**：三个来源 macro-F1 的平均值（ClimateCheck 占测试集 78%，避免它主导结论）。
- **判据**：5 个 seed 的平均 Δ 的分层 bootstrap 95% CI 下界 > 0，且至少 ⌈0.8·n⌉ 个 seed（5 个中至少 4 个）的 Δ > 0，才算"成立"；反方向同理为"显著更差"；其余为"不成立"。
- **分层 bootstrap**：每次先有放回地重抽 seed，再在每个 seed 内对测试样本做配对重抽，算两组 macro-F1 之差的平均值，重复 2000 次。它同时反映划分 / 训练的随机性和测试样本的抽样误差。
- 只用主训练 seed（训练 seed = 划分 seed）的结果；重复训练只进入训练噪声表。

### 5.2 第一阶段：试跑（seed 42，约 1.5 小时）

```bash
cd /root/autodl-tmp/Semi-vast/v3
nohup bash run_pilot.sh > logs/pilot.log 2>&1 &
bash logs/watch.sh            # 实时进度，Ctrl+C 退出不影响训练
```

内容：A、B 各用训练 seed 42 和 1042 训练一次，再训练 O；最后由 `evaluation/pilot_report.py` 打印下表并写入 `runs/r0.10_s42/outputs/pilot_report.json`。

| 编号 | 通过标准 | 不通过时怎么办 |
|---|---|---|
| C1 | 所有组的最佳验证点不在最后 10% 的步数内（已收敛） | 增加 `detector_total_steps`（例如 960） |
| C2 | 换训练 seed，A 和 B 的测试 macro-F1 变化都 < 0.02 | 训练噪声仍大：考虑每个集合训练 2 个 seed 取平均（主实验时间翻倍），或降低学习率并加步数 |

| C4 | O − A ≥ 0.10 | 提升空间不足，先与项目负责人讨论 |
| C5 | 每类的预测数 ≥ 该类金标签数的 50% | 检查类别权重；考虑 `class_weight_power: 1.0` |

**试跑未通过、需要改配置时**：改动会改变配置指纹，`run_all.py` 会拒绝在 `runs/` 里继续跑。复制一份配置（例如 `configs/config_b.yaml`），把 `paths.runs_dir` / `paths.results_dir` 改成新目录（例如 `runs_b` / `results_b`），然后：

```bash
CONFIG=configs/config_b.yaml nohup bash run_pilot.sh > logs/pilot_b.log 2>&1 &
```

改动 `[pool]` 设置（数据、extractor、伪标签生成）会让导入失败，那样所有 seed 都要从 extractor 重新开始，尽量避免。

### 5.3 第二阶段：主实验（A / B / Q / K / O × seed 42–46，约 7.5–9 小时）

```bash
cd /root/autodl-tmp/Semi-vast/v3
```

## 8. 已知限制

- **W / R / C 未修订**：复合权重仍用不带方向的 \|LogicScore\| 和没有信号的 Discourse；RL 奖励中 0.3·mean\|LS\| 近似常数（0.224 ± 0.006，ΔF1 项只有 ±0.007）。在第二阶段的 H2 结论出来之前不修订、不使用。
- **小集合重复使用**：见 3.2 节。Q 与 K 规模相同，H2 不受影响；H3（Q vs B）混有规模差异。
- **A 与 extractor 并不完全相同**：分类头、训练预算、补齐方式不同（3.1 节）。
- **extractor 过度自信**：没有改（它是方法的一部分），由按比例选样绕开。
- **dev 同时用于 extractor 和 detector 的模型选择**；测试集只在最后评估一次。
- **非完全确定性**：`cudnn.benchmark` 等使同一设置的重复结果有微小差异，这部分包含在训练噪声里。
- **5 个 seed 的 CI 仍然较宽**：判据同时要求 CI 与方向一致性；结论不成立时，要区分"效果为 0"和"功效不足"（看 CI 的宽度和均值）。

每少一层检查点，最坏情况多占：冻结层约 3.6 GB，可训练层约 4.2 GB；速度约快 1.2%。前面的层先不做检查点，因为前 6 层是冻结层，保留它们的激活更省显存。

### 11.2 改动与等价性

- 配置新增 `training.gradient_checkpointing_skip_layers: 18`（detector）和 `training.extractor_gradient_checkpointing_skip_layers: 24`（extractor，16 条 × 512 token，全部不做检查点）；实现在 `models/encoder_runtime.py`。
- 梯度检查点只决定激活是保存还是在反向时重算，不改变计算（transformers 5 默认 `use_reentrant=False` 并保留随机数状态）。实测：第 1 步的 loss 逐位相同；40 步的 loss 轨迹与全检查点的平均差 0.0025，和全检查点自己重跑两次的差（0.0026）相同。
- 这两个键不在配置指纹中（`common/fingerprint.py`），所以 `runs/`（`1f0a3098ce46`）和 `runs_f/`（`4342c1690f11`）的指纹不变，已有结果仍然有效，新的 seed / ratio 可以直接加进同一个目录。
- detector 的 `test_results.json` 新增 `checkpointed_layers` 和 `gpu_peak_gb`。
- 端到端验证（2026-11-05，`config_f.yaml`，输出写在临时副本目录，没有改动 `runs_f/`）：
  - detector，方法 F / seed 42：测试 macro-F1 **0.5542**（原 0.5502，差 +0.004；F 在同一划分换训练 seed 的差为 0.006），最佳步 240（原 480），训练 16.2 分钟（原 22.5 分钟，5090），峰值 84.0 GB（整卡最多用到 87.5 GB），GPU 平均利用率 96%，指纹仍为 `4342c1690f11`；

### 11.3 torch.compile：当时没有采用（2026-11-06 项目负责人决定采用，见第 12 节）

`torch.compile` 能再快约一倍（0.66–0.80 秒/步），显存也更少，但在 dropout 打开时训练动态与 eager 有系统性差异，原因没有查清：

| 对比（40 步，同一数据顺序） | 第 1 步 loss | 最后 20 步平均 loss |
|---|---|---|
| eager（两次） | 1.662481 / 1.662481 | 1.492 / 1.490 |
| compile（默认；前 18 层 / 全不检查点 / 全检查点） | 1.681775 | 1.345 / 1.379 / 1.382 |
| compile + `fallback_random`（dropout 用和 eager 相同的随机数） | 1.662440 | 1.448 |
| 关闭全部 dropout：eager vs compile | 1.670746 / 1.670335 | 1.250 / 1.259 |

- 关闭 dropout 时两者一致，说明编译后的前向和反向本身是对的；问题只出在训练时的 dropout。
- 单步梯度（同一 batch、同一 seed）：eager 两次的余弦相似度 0.999995；不开 dropout 时 eager 与 compile 为 0.9988；compile + `fallback_random` 为 0.9969。没有发现反向用错 mask，但 40 步后 loss 仍偏低 0.044（eager 重跑两次只差 0.002）。
- 如果要采用：它会改变训练动态，等于换了协议。需要新的 runs 目录，并在编译设置下重跑 ratio 0.1 的主实验，结果才能和 0.25 / 0.5 比较；按 0.7–0.8 秒/步估计，主实验约 3 小时。

### 11.4 注意事项

- **不要在 GPU 上同时跑别的任务**：并发没有加速（11.1），而且 detector 最坏情况占 84 GB，再加任务就会 OOM。`train_detector.py` 启动时发现显存已被占用会警告。
- 换回 32 GB 的卡：两个 `*_skip_layers` 都改回 0（与之前完全相同）。
- 每层的显存成本与每步的 token 数成正比；改了 batch、`pseudo_ratio` 或 `max_length` 时要重新测（基准脚本的做法：全部补齐到 `max_length` 跑几步，看 `torch.cuda.max_memory_allocated`）。

## 12. 改用 torch.compile（2026-11-06，项目负责人决定）

11.3 节的结论是：torch.compile 能再快约一倍，但会改变训练动态，采用就等于换协议。2026-11-06 项目负责人决定采用，并保留 dropout。

### 12.2 重编译上限（已处理）

每个 encoder 层的编译版本有：冻结 / 可训练（参数 `requires_grad` 不同）× 训练 / 评估（`grad_mode` 不同）× 首次静态形状 / 之后的动态形状，实测共 9 个。dynamo 默认最多 8 个，超过的部分会**静默退回 eager**（日志只有一行 `hit config.recompile_limit`）。所以代码把上限调到 64；之后又随机换了 14 种序列长度，版本数仍是 9，不会随长度增长。

为了防止以后再出现"一半编译"：detector 的 `test_results.json` 记录 `uncompiled_frames`（应为 0），不为 0 时训练日志警告，自动检查新增 **S8**。

2. **融合 teacher 相对置信度选样的优势只在 ratio 0.1 成立**。F − B 从 +0.040 降到 +0.005 / +0.006。原因在 teacher：ratio 0.1 时 extractor（0.507）弱于 A（0.529），融合 NLI 把选中伪标签的平衡后准确率提高 0.076；ratio 0.25 / 0.5 时 extractor 接近或超过 A，B 本身已经很准（0.714 / 0.762），融合只再提高 0.022 / 0.005，detector 上也就看不出差别。这与 10.9 节"teacher 越弱，融合的作用越大"一致，现在在 ratio 这个维度上也成立。
3. **只用置信度的半监督（H1）在 ratio 0.25 才成立**（+0.026），ratio 0.1 和 0.5 不成立。ratio 0.1 时 teacher 太弱；ratio 0.5 时提升空间太小。
4. **ratio 0.5 几乎没有提升空间**：O − A 只有 +0.020，不成立；O（0.610）甚至略低于 F（0.613），也只比 B 高 0.003。此时无标签池只剩 2161 条，有标签已有 2128 条，用金标签也提升不大。所以 ratio 0.5 的 F − A 小，不能解读为方法失效，而是这个设置本身没有多少可以提升的。ratio 0.25 时 F 拿到 O − A 的 86%（B 为 72%），也已接近上限。
5. **F3 在 ratio 0.25 / 0.5 上没有参考价值**：+0.12 / +0.13 主要是因为 A 变强后，测试时按固定 α = 0.5 融合 NLI 会把 A 拉低（A⊕NLI 为 0.481 / 0.480，低于 A 0.570 / 0.590）。F3 只在 ratio 0.1（A 与 NLI 强弱相当）时能排除"提升只来自 NLI 本身"。
6. **F 在每个 ratio 上都是最稳定的组**：跨 seed 标准差 0.009 / 0.009 / 0.005，均为各组最低（A 为 0.017 / 0.010 / 0.020，B 为 0.023 / 0.020 / 0.012）。
7. **LogicScore（c）作为可靠性信号随 ratio 变弱**：c 的 AUROC 从 0.583 降到 0.521，置信度从 0.583 升到 0.631。extractor 越强，它自己的置信度就越可靠，方向一致性提供的额外信息越少。方向二（10.5 节，"c 是更好的可靠性信号"）只在低标注比例下成立。
8. **机制不变**：ratio 0.25 / 0.5 的 10 个 run 中，融合改动了池中 40%–45% 的标签，但进入 F 的样本没有一条被改动（ratio 0.1 只有 seed 46 例外，见 10.9 节）。F 中 NEI 占 49%–65%。

**对论文定位的含义**：主要结论应写成"在低标注比例下（10%），证据感知的融合 teacher 显著优于只用置信度的 teacher"；ratio 0.25 / 0.5 作为"效果随标注增多而收敛"的分析，如实报告 F − B 不成立。teacher 强弱与 F − B 的对应关系（上面 teacher 表的 F − B 列）可以作为机制解释。

### 13.2 新方法

| 方法 | 训练数据 | teacher 与选样 | 预计 GPU 时间 |

#### 13.5.1 实现与可行性测试（2026-11-07，写于可行性测试之前）

**实现**（`training/tapt.py`；AT 接入 `train_detector.py`、`run_all.py`）：
- encoder 用与 detector 相同的方式（`AutoModel`）从 `cross-encoder/nli-deberta-v3-large` 加载；新的 MLM 头为 dense → GELU → LayerNorm → 与输入词向量共享的解码矩阵 + bias，只在被遮盖的位置算 logits。
- 输入与 detector 完全相同（claim 为第一段、证据为第二段，max_length 512），只用该 run 的 `unlabeled_pool.jsonl`，不用标签。遮盖按 BERT 的做法：选中的 token 中 80% 换成 [MASK]、10% 换成随机 token、10% 不变；特殊 token 不遮盖。
- 两个阶段：先冻结 encoder、只训练新的头 200 步（学习率 1e-4），避免随机初始化的头一开始的大梯度冲坏 NLI 权重；再全部参数一起训练，学习率 100 步 warmup 后保持不变。学习率不衰减，所以第 k 个 epoch 的快照等价于"只训练 k 个 epoch"。
- 固定的设置：batch 32（每个 epoch 120 步），AdamW（weight decay 0.01），梯度裁剪 1.0，bf16。每个 epoch 结束时在验证集文本上算 MLM loss（遮盖固定，不用标签）。
- AT 的微调与 A 完全相同（同一配置、640 步、按验证集选最佳步），只是 encoder 换成 TAPT 后的权重。TAPT 的设置和 α 一样写在代码里（`common/paths.py` 的 `TAPT_SETTINGS`），不进配置，指纹不变；没填之前 `run_all.py` 拒绝跑 AT。
- 耗时：每个 epoch 约 1.4 分钟（0.7 秒/步），按 A 的设置微调约 3 分钟。

**冒烟测试**（seed 42，只看验证集）：
- 对照：原始 NLI encoder 存成 `save_pretrained` 目录再读回（权重逐位相同），走 AT 的流程微调，最佳验证 macro-F1 为 0.5305（A 为 0.5252，在训练噪声以内）。流程本身不改变结果。
- 学习率 3e-5、遮盖 15%、TAPT 1 个 epoch：验证集 MLM loss 6.87（只训头后）→ 4.92；微调后最佳验证 macro-F1 只有 **0.4340，比 A 低 0.091**。在 NLI 模型上做 MLM，很快就破坏了它的 NLI 能力，所以下面的网格包括更小的学习率和更少的步数。

**可行性测试**（`tools/tapt_probe.sh`，seed 42，只看验证集 MLM loss 和微调后的最佳验证 macro-F1，不加载测试集；结果在 `runs_fc/r0.10_s42/outputs/tapt_probe/`）：

## 14. 标准半监督基线：FixMatch 与 FreeMatch（2026-11-14，写于运行之前）

### 14.1 共同设置

- 与第 13 节相同：`configs/config_fc.yaml`（指纹 `df8ea323b54a`），沿用 `runs_fc/` 中 ratio 0.1、划分 seed 42–46 的划分，每个 run 1 个训练 seed（= 划分 seed）。新方法 `FIX`（FixMatch）、`FREE`（FreeMatch）只作为方法名加入；它们的设置写在 `common/paths.py` 的 `SSL_SETTINGS`，不进配置，指纹不变，已有的 A / F 结果直接参与逐 seed 配对比较。
- **与 F 完全相同的部分**：从 NLI 交叉编码器初始化、冻结前 6 层；640 步、每 40 步评估、按验证 macro-F1 选最佳步；监督损失是带类别权重的 CE；每步 16 条有标签加 48 条无标签（`pseudo_ratio` 3 × `pseudo_batch_size` 16，与 F 每步的伪标签条数相同）；无标签损失的权重 λ 在 640 步内从 0.3 线性升到 0.7（所有组相同）；torch.compile。
- **唯一的区别是怎样利用无标签数据**：F 用融合 teacher 事先选好的伪标签集合；FIX / FREE 在训练中用 detector 自己对无标签池的预测做一致性训练。

### 14.2 方法（按 USB 的实现，Wang et al. 2022；2026-11-14 核对了 USB 源码）

- 无标签数据：整个无标签池（约 3850 对，不含标签），均匀随机抽样（没有标签，不能按类别平衡）。
- **弱增强 = 原文；强增强 = 两份回译之一（德语、俄语），每次随机取一份**。这与 USB NLP 数据集的做法相同（`semilearn/datasets/nlp_datasets/datasetbase.py`：`text` 是原文，`text_s` 从两份增强中随机取）。回译见 14.3。
- 每步：弱增强版本在不求梯度、训练模式（dropout 打开）下前向一次，得到概率 p；硬伪标签 ŷ = argmax p；强增强版本正常前向。无标签损失 = 48 条上 mask × CE(强增强 logits, ŷ) 的平均（USB 的 `consistency_loss(..., 'ce', mask=mask)`；等于本项目 `compute_joint_loss` 中把 mask 当作伪标签权重、`pseudo_weight_norm: mean`）。
- **FIX**：mask = [max p ≥ 0.95]（USB `p_cutoff`）。
- **FREE**：自适应阈值（SAT）。全局阈值 τ_t、类别分布 p̃ 与伪标签直方图 h 都是 EMA（动量 0.999，初值 1/3），每步用这 48 条弱增强概率更新一次；mask = [max p ≥ τ_t · p̃(ŷ) / max p̃]。另加公平性损失（SAF），权重 0.001（USB NLP 配置的 `ent_loss_ratio`；代码默认值 0.01 被配置覆盖），公式照搬 USB 的 `entropy_loss`。
- **与 USB 默认设置的差别（都是为了与本项目其他组的协议一致）**：
  - λ：USB 为常数 1.0，这里用所有组共用的 0.3 → 0.7；
  - 每步无标签条数：USB NLP 为 uratio 1，这里为 3（与 F 的伪标签条数相同）；
  - 监督损失：USB 为不加权的 CE，这里与所有组相同，用带类别权重的 CE；
  - 训练步数：USB NLP 为 102400 次迭代，这里为 640 步（所有组相同）。由此带来的已知后果：FREE 的 EMA 动量 0.999 在 640 步后只走完 1 − 0.999^640 ≈ 47%，τ_t 会一直明显低于模型的平均置信度，相当于早期训练阶段的宽松阈值。**不调动量，按默认值跑，如实报告 τ_t 的变化**。
- 诊断量（只记录，不用于任何选择）：每个评估窗口的 mask 比例、进入 mask 的伪标签相对无标签池金标签（`unlabeled_gold.jsonl`，只用于评估）的准确率；FREE 另记 τ_t。

### 14.3 回译

- 模型：Helsinki-NLP 的 `opus-mt-en-de` + `opus-mt-de-en`，`opus-mt-en-ru` + `opus-mt-ru-en`（MarianMT），用模型自带的解码设置（束搜索，束宽 4 / 4 / 4 / 6），每种语言得到一份确定的回译。
- 单位：claim 整句翻译；证据先按句切分（正则，按 `. ! ?` 后接空白与大写字母、数字或引号切分），逐句翻译后再拼回。每段证据只翻译前 450 个词（detector 的输入截断在 512 个 token，claim 加证据大约 380 个词之后的部分本来就看不到），强增强版本的证据就是这部分的回译。
- 范围：5 个 seed 无标签池中的全部 claim 和证据（去重后 2280 条 claim、6115 段证据），加上验证集（用于 14.4 第 1 项的检查）。不翻译有标签训练集和测试集。
- 缓存在 `processed/backtranslation/`（不在 runs 目录里，与配置指纹无关），由 `tools/backtranslate.py` 生成，可重复运行。

### 14.4 运行前的检查（不看测试集）

1. **回译是否改变标签（验证集，759 对）**：用 `models.nli_model`（F 用的同一个 NLI 交叉编码器）零样本预测原文与回译版本（输入构造与 `training/compute_nli_probs.py` 相同）。"方向翻转率" = 原文预测为 entailment 或 contradiction 的样本中，回译后预测变成相反方向的比例。三种回译方式：V1 claim 和证据都回译（USB 的做法，首选）、V2 只回译证据、V3 只回译 claim。**按 V1 → V2 → V3 的顺序，用第一个德语、俄语方向翻转率都 ≤ 5% 的方式；都不满足时，用两种语言平均翻转率最低的方式，并在结果中说明**。同时报告整体 argmax 一致率与回译前后 NLI 零样本的验证集 macro-F1。
2. 回译输出：没有空串；回译与原文的词数比在 [0.5, 2] 之间的单位占 95% 以上，否则停下检查。日志中每种语言打印 5 个例子。
3. 解码一个无标签 batch，确认弱增强是原文、强增强是回译。
4. FREE 的阈值与 SAF 损失：用随机输入与照搬的 USB 函数逐元素比对。
5. 冒烟测试：seed 42 上 FIX、FREE 各跑完一次，只看验证集（`--skip_test`），确认流程能跑通，记录耗时、显存、mask 比例。**冒烟测试的结果不用于修改任何设置**：只有程序错误才修，mask 比例接近 0 或 1 也按原设置正式运行。
6. `run_all.py --dry_run`：只执行 FIX、FREE，已有结果全部跳过。
